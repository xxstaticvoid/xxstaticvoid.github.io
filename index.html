Project Overview

The BoardSavr application is an Android mobile app designed to capture, process, and save chess board positions, so that the user may review them later. This project was built as improvement / complete revamp of a previous project that I made for my Mobile App Development class which was originally an app to keep track of spare parts in an inventory. You can view the app here The original app was intended for technicians to keep track of the number of spare parts that are currently available in inventory. With the new and revised artifact, instead of storing spare parts we are now storing chess postions.
The purpose of the BoardSavr app is to make it easier for a user to preserve the current state of a physical chess game by taking a picture of the board and converting that image into FEN notation. FEN notation is a standard format used to represent chess positions. By generating this notation automatically, the application allows users to save and review board states without manually entering every piece. The project uses technologies like CameraX, OpenCV, and Glide for capturing the board, processing the image, and displaying the image respectively.
The process begins in the camera interface, where the user captures an image of a physical chess board. The application then uses image processing techniques to locate, crop, and normalize the board so that it can be divided into 64 individual squares. Once the board image is properly aligned and scaled, the app analyzes each square to determine whether it is empty or occupied. For occupied squares, OpenCV template matching is used to compare the square image against piece templates created during a calibration step. In calibration mode, the user takes a picture of the board in the standard starting position from white’s perspective. The application saves templates for each piece type and later uses those templates to classify pieces in new board images. After all squares are analyzed, the board state is converted into FEN positional notation and can be stored along with the captured board image.

Software Design Improvements

This project demonstrates software design and engineering through several structural improvements made to the application. One of the main improvements was refactoring the code so that each part of the application has a clearer responsibility. Instead of placing all camera, image processing, database, and board conversion logic in one large activity class, the application was separated into focused classes and services. For example, the camera activity handles user interaction and image capture, while separate classes manage board conversion, template calibration, template storage, piece matching, and FEN generation.
This separation of responsibilities improves readability and maintainability because each class has a specific purpose. The image-processing logic is easier to understand because it is isolated from the Android user interface logic. The template matching logic is also easier to test and improve because it is handled separately from the camera capture process. This structure makes future changes more manageable, such as improving the matching algorithm, changing the database schema, or adding new board review features.

Algorithms and Data Structures

This project demonstrates algorithms and data structures through the logic used to process the chess board image and convert it into structured board data. The main algorithmic challenge was transforming a real world image into a usable digital representation of a chess position. The application uses computer vision and image processing techniques to crop and normalize the board, convert to grayscale, divide it into an 8x8 grid, and analyze each square individually.
A major improvement was separating empty-square detection from piece classification. Instead of attempting to classify every square as a piece, the application first determines whether a square is empty or occupied. This improves accuracy and performance because template matching only needs to run on squares that likely contain pieces. The app uses image data such as edge ratio and contrast to help determine whether a square contains a piece. This validation step reduces false matches and prevents empty squares from being incorrectly classified as chess pieces.
The template matching process also demonstrates the use of searching and comparison logic. Each occupied square is compared against saved piece templates, and the best match is selected based on similarity. The board itself is represented as a 2d data structure, where each row and column corresponds to a chess square. Once the pieces are classified, this board representation is converted into FEN notation by scanning each row, counting consecutive empty squares, and appending the correct piece symbols. This demonstrates practical use of arrays, searching, comparison, validation, and data transformation.

Database Enhancements

The project demonstrates database skills through the way chess board information is stored, retrieved, and organized. Instead of only capturing images temporarily, the application saves meaningful board records that can be accessed later. Each saved board can include information such as the captured image filename, date, description, and generated FEN notation. This allows the user to build a collection of saved chess positions rather than losing the board state after the image is processed.
The database portion of the project supports persistent storage, which is important for making the application useful beyond a single session. The app organizes saved board data so that records can be retrieved and displayed later in the application. This required planning how board information should be structured and how different pieces of data relate to one another. For example, the image file and FEN notation both describe the same saved board state, so they need to be stored together in a consistent record.

Reflection and Future Work

Improving my Chess Board Saver application helped me better understand how much planning and refinement goes into turning a basic idea into a more complete software project. At the beginning, the goal seemed simple: take a picture of a chess board, detect the pieces, and save the board state as FEN notation. However, as I worked through the project, I learned that each part of that process introduced its own technical challenges. The project required me to combine Android development, image processing, data storage, and software design into one working application.
One of the biggest lessons I learned is that computer vision can be very persnickety. And this is a big understatement. Small changes in lighting, camera angle, board color, piece shape, or image rotation can create major differences in how the image is processed. Even after I was able to crop and normalize the chess board, extracting accurate board data still required careful testing. And even still isn't all that dependable. I had to think about how the board was divided into squares, how to detect whether a square was empty, and how to compare occupied squares against saved templates. This taught me that computer vision is not just about applying an algorithm, but its more about breaking down the big problem into smaller steps. It also requires debugging, validating assumptions, adjusting thresholds.
I also improved my understanding of Android development. Managing the camera involved more than simply taking a picture. I had to consider user permissions, CameraX behavior, image orientation, background processing, and how the captured image differed from the preview shown on screen. I also became more aware of thread safety because image capture and processing should not block the main user interface thread. Keeping longer image-processing work separate from UI updates made the application more stable and responsive.
There are still several future enhancements I could make. One improvement would be to make the template matching more robust under different lighting conditions or possibly add support for multiple chess sets. Another possible enhancement would be to allow users to manually correct detected pieces before saving the final FEN notation. I could also add search, sorting, or filtering features for saved boards, such as sorting by date or searching by description. In the future, I could even explore machine learning-based piece recognition instead of relying only on template matching. All in all, I plan to continue working on this app and eventually publish it to the Play Store once I feel it is good enough.
Overall, the BoardSavr project demonstrates my growth as a computer science student because it required me to apply concepts from several areas at once. I had to design cleaner software architecture, improve algorithmic logic, handle real application data, and debug difficult image processing problems. The project also taught me the importance of testing each stage of a system independently. By improving this application, I gained more confidence in building software that is not only functional, but also organized, maintainable, and expandable.
